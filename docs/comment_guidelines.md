# NanoAI Comment Guidelines

本规范用于统一 NanoAI 各模块（NanoAIFlow、NanoAI_RKNN、NanoAI_NCNN）的注释风格与质量标准，目标是让代码在高并发、高模板复杂度场景下依然可读、可维护、可审查。

## 1. 适用范围

- C/C++ 源码与头文件。
- CMakeLists 与 cmake 配置模板。
- 示例代码与测试代码（以解释意图为主，不写冗余注释）。

## 2. 注释总体原则

1. 解释为什么，不只解释做什么。
2. 优先解释复杂路径：并发、内存、生命周期、异常传播、顺序保证、性能权衡。
3. 注释必须与代码保持同步，代码变更时同步更新注释。
4. 禁止无信息量注释（如“给变量赋值”“进入循环”）。
5. 用词精确、短句优先，避免模糊词（例如“可能”“大概”）。

## 3. 必须补充的注释层级

### 3.1 文件级注释（必须）

每个核心文件建议在文件头说明：

- 文件职责（该文件解决什么问题）。
- 关键设计目标（例如吞吐优先、顺序一致性、可移植性）。
- 关键约束（线程安全假设、ABI 假设、平台要求、C++ 标准要求）。

### 3.2 类型级注释（类/结构体/枚举，必须）

需要说明：

- 类型角色（例如调度器、配置对象、守卫对象）。
- 生命周期语义（可拷贝/可移动/不可复制原因）。
- 线程安全语义（线程内使用、外部同步、内部同步）。

### 3.3 函数级注释（公共接口必须，复杂私有函数建议）

需要说明：

- 输入参数语义（所有权、是否可空、单位、取值范围）。
- 返回值语义（单值/聚合值/错误值）。
- 异常与错误传播方式。
- 并发行为（阻塞、唤醒、锁粒度、顺序保证）。

### 3.4 变量/成员注释（关键状态必须）

需要说明：

- 该变量表示的状态含义。
- 读写时机与同步关系（是否受锁保护、是否原子）。
- 单位与范围（例如 us、ms、token 数）。

### 3.5 代码段注释（复杂段必须）

对以下片段补注释：

- 并发控制与锁顺序。
- 无锁/低锁优化路径。
- 批处理与自适应参数调节逻辑。
- 对性能敏感的内存分配策略（例如池化、对象复用）。

## 4. 推荐注释模板

### 4.1 文件头模板

```cpp
// File: xxx.hpp
// Brief: 一句话说明文件职责。
//
// Design notes:
// - 目标 1
// - 目标 2
// - 约束 1
```

### 4.2 类注释模板

```cpp
// XxxManager 管理 ...
// 线程安全：...
// 生命周期：不可复制、可移动（原因：...）。
class XxxManager { ... };
```

### 4.3 函数注释模板

```cpp
// 作用：...
// 输入：a 表示 ...，单位 ...
// 返回：...
// 异常：...
// 并发：...
ReturnType run(A a);
```

## 5. CMake 注释规范

CMake 注释重点说明构建与打包意图：

1. 目标类型与用途（INTERFACE/STATIC/SHARED）。
2. 编译特性与版本约束（例如要求 C++20 的原因）。
3. 安装导出逻辑（导出目标、Config 文件、兼容变量）。
4. 可选开关（测试、示例、打包）对产物的影响。
5. 测试注册块的分类意图（功能正确性、性能回归、一致性验证）。

## 6. 示例与测试注释规范

1. 示例代码注释优先解释“使用姿势”和“推荐参数”。
2. 测试代码注释优先解释“断言目的”和“回归风险点”。
3. 避免对每行断言做重复描述。

## 7. 注释风格约定

1. 中文为主，必要术语可保留英文（例如 batch、token、alias）。
2. 一条注释只表达一个核心意图。
3. 行宽建议不超过 100 字符，长说明拆成多行。
4. 与代码缩进对齐，避免视觉错位。

## 8. 反例（应避免）

1. 与代码含义冲突的陈旧注释。
2. 复制粘贴但未改变量名或行为描述。
3. 解释语法而非语义（例如“这里调用函数”）。
4. 将业务约束写在提交说明里但不写入代码注释。

## 9. 评审检查清单

在提交前至少确认：

1. 新增核心文件是否有文件级注释。
2. 新增类/核心结构体是否说明线程安全与生命周期。
3. 新增并发或性能关键路径是否有代码段注释。
4. CMake 改动是否说明构建/安装影响。
5. 注释是否与当前实现一致。

## 10. 维护建议

1. 重大重构后执行一次“注释一致性复查”。
2. 文档与代码注释冲突时，以代码行为为准并立即修正文档。
3. 若模块需要更严格规则，可在子模块 docs 中补充专用规范，但不得弱化本规范。
